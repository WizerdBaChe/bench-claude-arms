# G4 手動驗收清單（GUI）

> 自動評分器**不評** G4。依 CLAUDE.md：渲染給人看的東西，綠燈測試不等於畫面對 —
> 我不會宣稱這四項通過，由你實跑確認。
>
> 本清單設計為**非作者可盲跑**：每一步都有具體動作與預期觀察，不需要讀原始碼。
> 四個受測組各跑一次，同一份清單。

## 前置

1. 開啟 `D:\BenchRuns\<run-id>\`，找到 `bin\Release\` 下的執行檔。
2. 準備一個測試資料夾（**不要用 holdout 的 fixture-tree**，那是隱藏驗證集）：
   隨手放 5–6 個檔案，至少包含一個中文檔名、一個含空格的檔名、一個無副檔名的檔案。

## 快樂路徑（happy path）

| # | 動作 | 預期觀察 | 結果 |
|---|---|---|---|
| H1 | 雙擊執行檔 | 視窗在 10 秒內出現，沒有例外對話框，沒有殘留 console 視窗 | ☐ |
| H2 | 用介面選擇上面那個測試資料夾 | 檔案清單出現，數量與資料夾內的**檔案數**相同（子資料夾不應列入）| ☐ |
| H3 | 加一條規則：全部轉小寫 | **在還沒套用之前**就能看到「原名 → 新名」的預覽 | ☐ |
| H4 | 按下套用／執行 | 資料夾內檔案真的被改名，且與預覽顯示的一致 | ☐ |
| H5 | 找復原功能並使用 | 檔名回到原狀 | ☐ |

## 壓力路徑（stress path — 項數不少於快樂路徑）

| # | 動作 | 預期觀察 | 結果 |
|---|---|---|---|
| S1 | 選一個**空資料夾** | 不當掉；顯示「沒有檔案」之類的訊息，而不是空白畫面 | ☐ |
| S2 | 加一條會讓兩個檔案撞名的規則（例如把數字全部刪掉）| 預覽把撞名項**標示出來**；套用時不會靜默覆蓋掉檔案 | ☐ |
| S3 | 加一條會產生非法字元的規則（在檔名尾端插入 `:`）| 該項被標為無效，且**不會**被實際套用 | ☐ |
| S4 | 快速連按套用鍵 5 次 | 不會重複套用 5 次、不會當掉、不會產生 `a_1_1_1_1_1` 這種疊加結果 | ☐ |
| S5 | 規則清單留空就直接套用 | 不當掉；要嘛擋下來，要嘛視為無變更 | ☐ |
| S6 | 選一個檔案很多的資料夾（≥200 個）| 介面不永久凍結；即使慢也要有進度或忙碌指示 | ☐ |
| S7 | 套用途中把該資料夾在檔案總管中刪掉／改名 | 出現可讀的錯誤訊息，**不是**未處理的例外堆疊 | ☐ |
